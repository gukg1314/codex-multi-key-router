# Codex 多 Key 路由 v1.1 修复、托盘常驻与全套图标

## 概要

修复 5 个已定位问题：同名模型重复、工具调用报错断流、拉取后列表不刷新、搜索框断字、macOS 状态栏 / Windows 托盘常驻；并用 `Codex多Key路由工具/icon.png` 做一套 Mac、Windows 通用图标（应用、状态栏、托盘、界面左上角）。拉取与路由底层逻辑不动。版本 1.1.0，仍在 Mac 上交叉编译出 Windows exe 与 macOS 未签名 dmg。

## 改动方案

**1. 同名模型只保留一条**
- 新增「模型身份」归一化：小写后去掉 `/ _ . -` 与空格再比较，`GPT-5.6 Sol`、`gpt-5.6-sol`、`gpt5.6.sol` 视为同一个模型。
- `merge_catalog()` 在原有 slug 去重之外，按该身份把与 Key 条目同名的官方条目一并剔除；谁生效由既有 `model_priority` 决定，未配置时沿用现状（Key 顺序优先）。
- 优先级页「其它同名来源」改用同一归一化规则，保证官方选项可见、可切回；切回官方并刷新模型列表后，Key 条目消失、官方条目恢复。
- 优先级页补一行说明：切换来源会替换 Codex 列表里的同名条目，刷新模型列表后生效。
- manifest 结构、slug 生成规则、拉取流程都不改。

**2. 工具调用报错不再断流**
- 桥接解码失败（未注册工具名、自定义工具参数非法）时不再终止流：
  - 先纠偏：工具名忽略大小写、去掉非字母数字字符、去掉 `_` + 10 位十六进制后缀后与注册表唯一匹配，命中就按该工具处理；
  - 纠偏失败就降级成一条中文说明文本（含模型名与原始工具名），与模型本轮文本一起正常返回；
  - 合法调用照常输出，只有非法项降级；整轮无文本且工具全部非法时也必须输出说明文本，避免 Codex 收到空回复；
  - 日志保留 WARNING（模型、原始工具名、原因），metrics 增加降级计数。
- Key 与模型页每个模型增加「图片输入」勾选，写入 `settings.model_overrides[模型]` 的 `input_modalities` / `supports_image_detail_original`，默认保持支持图片；关闭后刷新模型列表生效；桥接层若仍收到图片，替换为文字占位。

**3. 拉取后立即刷新**
- 「测试连接 / 拉取模型」完成后清掉前端模型勾选缓存（DRAFT），用最新 `discovered_models` 重建，再重载 state，并提示发现模型数量。
- 当前选中 Key 的列表就地重渲染，不需要切页签。

**4. 搜索框不再断字**
- 模型表格拆成独立容器，输入时只重渲染表格，不重建整页，输入框节点与焦点保持不变。
- 处理中文输入法组合事件，组合期间不重渲染。

**5. macOS 状态栏 + Windows 托盘**
- macOS：新增 NSStatusItem；关闭窗口只隐藏、不退出；菜单栏菜单「打开主界面 / 退出」；退出与 Cmd+Q 都走关闭流程。
- Windows：拦截关闭消息，弹二次确认框（复用界面现有弹框样式，按钮为「最小化」「关闭工具」；页面 1.5 秒无响应时默认最小化）；最小化隐藏窗口并显示右下角托盘图标；托盘右键菜单「打开主界面 / 退出」、双击恢复。
- 「关闭工具」统一流程：调 direct 切回官方直连 → 调 stop 停路由 → 退出并移除托盘图标，总超时 10 秒；开机自启开关保持不变。
- 单实例：启动时先探测管理端口 +1 上的实例通道，已有实例就发 `show` 唤起窗口后退出，否则自己监听；端口被其它程序占用时允许再开窗口，不阻塞启动。
- Windows 托盘与窗口钩子用 x/sys + user32/shell32 宽字符 API，不新增第三方 Go 依赖。

**6. 全套图标（源图 icon.png，1254×1254 透明底）**
- 源图复制为 `packaging/assets/app-icon.png`，作为唯一图标源。
- macOS 应用图标：构建时生成 16–1024 全尺寸 iconset → `AppIcon.icns`，写入 Info.plist 的 `CFBundleIconFile`，Dock 与 Finder 生效。
- Windows 应用图标：构建时生成 16/32/48/64/128/256 多尺寸 ICO，用 go-winres 写进 `CodexMultiKey.exe` 与 `uninstall.exe`；工具下载失败时降级为不嵌 exe 图标，构建不中断。
- macOS 状态栏图标：构建时从源图派生 18px / 36px 镂空剪影（实心形状 + 亮部镂空，18px 实测可辨认），随 app 资源打包，`NSImage` 设 template 后自动适配深浅菜单栏。
- Windows 托盘图标：源图派生 16/32 彩色 ICO，go:embed 进 launcher，运行时创建 HICON。
- 界面：生成 `ui/logo.png`（60×60）替换左上角「C」方块，同时作为 favicon；两个打包脚本把该文件一起复制到 UI 目录。
- 源图缺失时全部降级为系统默认图标与现有「C」方块，不阻塞构建。

## 接口与数据变化

- `merge_catalog()` 官方同名条目按归一化身份剔除，manifest 保持 version 2 结构不变。
- 新增 `PUT /api/models/overrides`：body `{upstream_model, input_modalities, supports_image_detail_original?}`，写 settings 并返回最新 state。
- `/api/state` 的 `models[]` 增加 `input_modalities` 供界面显示开关。
- launcher 平台层新增「最小化」「关闭工具」回调与单实例 `show` 通道。

## 测试与验收

- Python 单测：同名去重三种情况（Key 覆盖官方、显式指定官方、不同写法的同名识别）、模型能力开关读写与 state 反映、工具调用降级与纠偏、无文本兜底；跑 `python3 -m unittest discover -s tests -q`。
- Go：单实例通道与关闭流程 HTTP 调用做可注入 stub 单测；`go test ./...` 过 launcher / installer，并完成两端交叉编译。
- 图标校验：icns / ico / logo.png 尺寸与内容正确；状态栏 18px 剪影实机不糊。
- 手工验收（Mac 与 Windows 各一遍）：同名模型只剩一条且优先级切换正确；带图任务不再直接失败，关掉图片开关后不再发图；拉取后列表立即出现；中文连续输入不断字；macOS 关窗口菜单栏图标在、可恢复，Dock 图标正确；Windows 关窗口弹框、最小化到托盘、恢复、关闭工具会切回官方直连并停路由，exe 图标与托盘图标正确；中文用户名路径日志正常。
- 每项改动单独提交，产出 `CodexMultiKey-1.1.0-arm64.dmg` 与 `CodexMultiKey-Setup-1.1.0.exe`。

## 假设与默认

- 同名模型未配置优先级时默认按 Key 顺序（Key 优先），与现状一致，界面可改回官方。
- 「关闭工具」= 切回官方直连 + 停路由 + 退出界面；开机自启开关不因关闭而改变。
- 开机自启仍只静默启动后台服务，不弹窗、不显示托盘图标；打开界面后关闭窗口才驻留托盘 / 菜单栏。
- 版本号 1.1.0，Windows 包继续在 Mac 上交叉编译；不使用 .bat / .ps1，新增 Win32 调用全部走宽字符 API。
